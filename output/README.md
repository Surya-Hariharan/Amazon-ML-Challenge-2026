# output/

Holds only the two final submission TSVs produced by
`code/src/run_pipeline.py --mode test`:

- **`matching_results.tsv`** — final entity matches. The only file scored on the
  leaderboard. Header: `source1_entity_id\tmatched_entity_ids`.
- **`candidate_pairs.tsv`** — the exact candidate set the matching model scored to
  produce `matching_results.tsv` (not an earlier/looser blocking pass). Not scored, but
  required in the submission zip and used to audit blocking recall/reduction ratio.
  Header: `source1_entity_id\tcandidate_entity_ids`.

Both are written by `src/io_utils.write_submission()`, which enforces the formatting
rules itself (tab-separated, no duplicate rows/IDs, no spaces or quoting in ID lists,
one row per test S1 entity, empty string for no matches).

## Before every submission

Always validate both files and confirm `PASS`:

```bash
python3 utils/validate_submission.py \
  --matching output/matching_results.tsv \
  --candidate output/candidate_pairs.tsv \
  --test-dir dataset/test
```

See [`../docs/problem-statement.md`](../docs/problem-statement.md)
for the full format specification and the final submission zip structure, and
[`../utils/README.md`](../utils/README.md) for what the validator checks.

The TSVs are regenerated by every full pipeline run and are not versioned; only this
README is tracked. Packaging steps are in
[`../docs/submission.md`](../docs/submission.md).
